# 赛时提示词清单

> 按赛程阶段排列，可以直接复制。每条都对应本仓库里的一份规范文件——**提示词负责"让 AI 按规矩做事"，规范文件负责"规矩本身"**。
>
> 使用前提：AI 是助手，不是替身。每条提示词都内含人工复核要求，删掉那些要求会同时删掉它的价值。

---

## 用法

1. 开赛前把整个仓库 clone 到本地，工作目录按 [`05-directory.md`](05-directory.md) 建好。
2. 每次让 AI 干活，先贴对应阶段的提示词，再把规范文件的**相对路径**给它（让它自己去读）。
3. AI 的输出一律当草稿。**数值、公式、结论必须由人核对原始数据与程序输出。**

占位符用 `{{ }}` 标出，替换成你的实际内容。

---

## 阶段 0 · 读题体检

用在：拿到题目后的头两小时，三题都过一遍。

```
你是数学建模队伍的读题助手。现在我们只做一件事：把题目读准确，不做任何解法。

题目原文：{{粘贴题干，或给出文件路径}}

请按以下结构输出，不确定的地方直接标"原题未说明"，不要猜：

1. 题目到底要我们交付什么（逐问列出，含附件要求）
2. 已知条件清单：每条注明"来自题干"还是"来自附件数据"
3. 数据情况：文件名、量级、缺失情况、口径（单位/时间范围/统计口径）
4. 需要我们自己做的假设（原题没说、但建模必须定的参数）
5. 我可能读错的地方：列出 3 处最容易被误读的表述，并说明两种读法会导致什么不同结论

禁止：不要给建模思路，不要提算法名字。这一步只校对理解。
```

**为什么要"我可能读错的地方"这一项：** 国赛的失分很大一部分不是模型不好，是第一问就读偏了。让 AI 主动找歧义，比让它给方案有用得多。

## 阶段 1 · 锁题决策

用在：20:00 前决定做哪题。

```
我们已读完 A/B/C 三题，现在必须在 {{HH:MM}} 前锁题，之后不换题。

三题的读题笔记：
A：{{粘贴阶段 0 的输出}}
B：...
C：...

按三个维度给我一张决策表，每项 1-5 分并说明理由：

1. 数据可得性（附件够不够支撑完整解答，缺什么）
2. 创新空间（有没有能做出差异的切口，还是只能套标准模型）
3. 限时闭环（以我们三个人的能力，74 小时内能不能四问都给出可验证结果）

最后给出：推荐哪题 + 一条最强反对理由（如果我选了它，最可能死在哪）。

不要为了让我好受而给平衡的结论。我们需要一个明确的推荐。
```

## 阶段 2 · 建模方案

用在：第一问开工前。

```
题目第一问要求：{{粘贴}}

建模要求：
- 先给 2 个候选方案，不要只给一个
- 每个方案写清楚：核心假设、变量与符号、目标/约束、需要的数据、求解难度、可验证性
- 明确说出每个方案"最可能被质疑的地方"

然后做对抗：
- 方案 A 相比方案 B，在什么情况下会明显更差？
- 如果评委只问一个问题就能问倒这个方案，那个问题是什么？

最后给一个推荐 + 一句话理由。不要综合两个方案各取一半。

输出后请自查：所有符号是否在第一次出现时定义？假设是否与题目条件冲突？
```

## 阶段 3 · 求解代码

用在：方案定了，要落成代码。

```
按下面的方案写求解代码，要求能在我本机直接跑出结果。

方案：{{粘贴阶段 2 的最终方案}}
数据文件：{{路径}}
输出要求：{{需要哪些中间结果和最终结果}}

硬性要求：
1. 只用标准科学计算栈（numpy / pandas / scipy / matplotlib / sklearn / openpyxl），不引入需要额外申请许可的求解器
2. 所有路径用相对路径，工作目录假设为脚本所在目录
3. 随机过程必须固定 seed，并在输出里打印 seed
4. 关键中间结果打印到 stdout（便于我核对，之后可以关掉）
5. 结果同时写一份 JSON（数值锚点，用于结果锁定），字段名自解释
6. 代码跑不通时不要静默 try/except 吞掉异常

写完后请列出：这段代码里哪 3 处最可能算错，我要手工核对什么。
```

**这一条对应 [`10-reproducibility.md`](10-reproducibility.md)：** 相对路径 + 固定 seed + 结果 JSON，是"换个目录还能跑"和"数字能对上"的前提。

## 阶段 4 · 结果检验

用在：每问出结果之后，写论文之前。

```
结果已出来：{{粘贴结果或 JSON}}
模型类型：{{物理机理 / 运筹优化 / 数理统计 / 综合评价，选一个}}

请按《赛时四类模型检验清单》（docs/09-model-checks.md）逐项检查，对每一项给出：
- 做了 / 没做 / 不适用
- 如果做了，结论是什么
- 如果没做，需要补什么

特别注意：
1. 有没有"看起来合理但其实是 bug"的结果（量级异常、单调性反了、边界情况爆炸）
2. 敏感性：哪个参数稍微一动结果就变？变了多少算不能接受？
3. 这个结果和题目要的结论是不是同一回事（别算出个漂亮数字但没回答问题）

最后给一个判断：这个结果能不能进摘要。
```

## 阶段 5 · 画图

用在：正文主体写完后集中出图。

完整版见 [`04-figures.md`](04-figures.md) §9，核心是：

```
现在要画一张图。请严格按 docs/04-figures.md 执行：
1) 先问我三个问题：数据在哪个文件、想说明哪个结论、图放论文哪一节
2) 按 §2 决策表选库与风格
3) 出图后自查：坐标轴标签、单位、图例、字号是否达到论文印刷要求
4) 告诉我这张图能支撑的那句话怎么写
```

**关键在最后一句。** 图不是装饰，每张图都要对应正文里一句有数据支撑的结论。凑数的图会被看出来。

## 阶段 6 · 摘要

用在：正文基本定稿后。摘要是最后写的，不是最先写的。

```
正文已完成，现在写摘要。要求：

1. 每问一段，结构统一为：问题 → 方法（模型名称）→ 关键结果（具体数值）→ 验证结论
2. **所有数值必须是正文里出现过的**，不许新造、不许四舍五入到失真
3. 模型名称必须与正文一模一样，一个字都不能改
4. 加粗只用于：核心方法名、关键数值。每段不超过 3 处，且分散，不要连续整句加粗
5. 三问的句子结构不要雷同——不要让评委看出是同一个模板套的
6. 不要出现"效果较好""误差较小"这类含糊表述，一律换成数值或百分比

写完后，逐条核对：摘要里提到的每一个模型、每一个数字，能否在正文对应位置找到？
列出找不到的，我来改。
```

要避开的典型问题（[`01-battle-card.md`](01-battle-card.md) 里记的）：摘要写了正文没有的方法名、含糊的定性结论、整段加粗导致视觉一团黑。

## 阶段 7 · 定稿改写

用在：正文要交给评委之前。

完整操作规范在 [`07-aigc-compliance.md`](07-aigc-compliance.md)。**前提是读它，而不是只读这段提示词**，因为这里的每一条都是那份规范里的铁律。

```
按 docs/07-aigc-compliance.md 逐节改写。现在只改 §{{章节号}}，不要动其它章节。

硬性约束：
1. 只做最小改写：保留全部事实、数据、公式、引用结构。改写的是表达，不是内容
2. 不要整篇统一变换——句长和连接词要有自然起伏，不要每段一个形状
3. 改完把这一节和上下文的术语核对一遍，模型名/符号不能漂
4. 输出改写后的文本 + 一份"改了什么"的说明（哪几句动了、为什么）

不要提供任何"降低检测率"的评估或承诺。这是合规改写，不是规避。
```

## 阶段 8 · AI 使用记录

用在：收尾，提交前。

```
根据本次比赛的完整对话记录，按 templates/ai-usage-log.md 的格式生成 AI 使用记录。

要求：
1. 如实记录：工具名称与版本、使用环节、使用目的、采纳情况
2. 提示词部分写"主要提示词类型 + 典型示例"，不必逐字全录，但不能编造
3. "人工复核"一栏必须写清楚人工做了什么，不要写"已复核"三个字敷衍
4. 列出你判断"AI 输出未被采纳"的环节——这些也要写进去，未采纳也是使用记录的一部分

生成后提醒我：还有哪些环节我可能在别处用过 AI 但没记进来。
```

**这份记录的用途是提交给组委会，不是给自己看的。** 它对应《AI 工具使用详情》的要求，写虚了比不写风险更大。

---

## 一条贯穿始终的原则

上面每条提示词都带着"核对""列出你要自查的地方""告诉我哪里可能错"这样的尾巴。这不是客套。

AI 在数学建模里最危险的不是算错，是**流畅地给出一个错的答案**，而你在 74 小时里没有余力逐字验证。让它主动标注不确定性，比让它更努力地输出，有用得多。

---

*提示词会随着模型变化而失效，方法论不会。改提示词之前先改流程。*
